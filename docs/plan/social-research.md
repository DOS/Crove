# Crove Social: reference research

> 2026-10-16. Input to the [Social plan](social.md). Three read-only research passes: Postiz (upstream and the archived DOS/Crove-Post fork), other open-source and commercial schedulers, and the platforms' official publishing docs. Nothing from these repos was run. [U] marks a claim not verified against a primary source.

## 1. License policy for references

Crove's CLA lets the project owner relicense contributions, including under commercial terms (CLA.md, part 1 §2). Third-party code cannot be relicensed that way, whatever its license. So: we study designs, behavior and platform knowledge from these projects and write our own code from the platforms' public docs. We do not copy code, including from MIT or Apache projects, unless an ADR accepts a specific file with attribution.

## 2. Postiz (gitroomhq/postiz-app, AGPL-3.0, about 37k stars)

- **Fork state.** DOS/Crove-Post (archived, branch `dev`) is 185 commits ahead and 73 behind upstream `main`, merge base 2026-10-09 (v2.25.1). Fork delta: a DOS.Me broker for Reddit token refresh, billing UI, Crove branding.
- **Stack.** NestJS 11 API and orchestrator, Next.js 16 frontend, Prisma 6 on Postgres 17, Redis, and since 2026-01-05 (PR #1157) Temporal instead of BullMQ. Self-host is 8 containers (Temporal, a second Postgres, Elasticsearch, admin and UI).
- **Providers.** About 36: X, LinkedIn (member and page), Facebook, Instagram (two logins), Threads, TikTok (two), YouTube, Pinterest, Reddit, Bluesky, Mastodon, Telegram, Discord, Slack, GMB, WordPress, Medium, Dev.to, Hashnode, Lemmy, Nostr, VK and others. No Zalo.
- **Provider interface.** `generateAuthUrl`, `authenticate`, `refreshToken`, `post`, optional `postPending` + `checkPostStatus` (`pending | ready | completed`) + `finalizePost` for two-phase platforms, `comment`, `analytics`, `postAnalytics`, `maxLength`, `checkValidity`, flags such as `isBetweenSteps` (pick a page after OAuth) and `refreshCron`. Errors are classified as `RefreshToken`, `Disconnect`, `BadBody` (not retryable), `PublishedWithError`, `NotEnoughScopes`.
- **Reliability.** Publishing activities run at most once; the workflow retries only when the worker provably never started the call. Any other timeout ends as "could not confirm, check your account" (v2.23.0, PR #1813, after duplicate-post incidents #1321 and #832). There is no provider idempotency key and no `publishing` state in the database.
- **Known pain.** Heavy self-host footprint (#1570: 32 Temporal workers idle at about 27% CPU), startup races and health checks that pass while posts sit queued (#1550, #1748), frequent provider OAuth breakage (#1582, #1694, #1773), TikTok audit rejections over UX (#1563), 12 copies of a 700-line versioned workflow, settings stored as JSON strings.
- **No approval workflow.** Roles are only superadmin, admin and user; RBAC and approval are open requests (#1758). Native approval is a gap Crove fills.
- **Worth learning from.** Two-phase publish contract ("once `finalizePost` went through, status must be `completed`, never `ready` again"); per-provider task queues with concurrency limits (Reddit 1, LinkedIn 8, Instagram 400); per-channel posting times; a public preview page with anchored comments for client review; sets and signatures; post-publish "plugs" (auto-repost, reply at a likes threshold); public API, SDK, n8n node, MCP server.

## 3. Other projects

| Project | License, stack | Why it matters |
|---|---|---|
| [OpenPost](https://github.com/getopenpost/openpost) | AGPL-3.0, Go + SvelteKit, SQLite or Postgres; very active (v7.21.1, 2026-10-14) | The most careful publish-exactly-once design found: a write fence before the first visible provider call, results carrying a submission state (`not_sent`, `accepted`, `pending`, `rejected`, `unknown`) and a retry safety (`safe`, `idempotent`, `reconcile_only`, `never`), one in-flight attempt per operation (partial unique index), `manual_resolution` for unknown outcomes. Approval bound to a revision and content, media and settings hashes, with the actor's origin (browser, API, MCP, CLI, worker) |
| [BrightBean Studio](https://github.com/brightbeanxyz/brightbean-studio) | AGPL-3.0, Django + Postgres, database-backed worker, no Redis (2.5k stars, since 2026-03) | Postgres-only publishing with row locks; a confirmation sweep asks the platform about posts stuck in `publishing` instead of republishing; staged approvals; slots plus named queues; per-provider rate-limit config; media fetched once per asset |
| [TryPost](https://github.com/trypostit/trypost) | AGPL-3.0, Laravel | Written-down queue-slot rules (below); agent-first API and MCP where agents follow the same rules, limits and approvals as people |
| [Mixpost](https://github.com/inovector/mixpost) Lite | MIT, Laravel | Small provider contract plus a declarative capability object (limits, media mix, post types) that drives validation and preview; rate limits tracked per app and per account |
| [Post for Me](https://github.com/DayMoonDevelopment/post-for-me) | AGPL-3.0, NestJS + Supabase + Trigger.dev | Open-source unified posting API, one module per platform |
| Ayrshare, [Zernio](https://docs.zernio.com) (formerly Late) | Closed APIs | API shape for our public API and MCP: one post resource with per-target entries and per-target status (`partial`), an idempotency key, 409 on the same content to the same account within 24 h |
| [langchain-ai/social-media-agent](https://github.com/langchain-ai/social-media-agent) | MIT, LangGraph | Human-in-the-loop drafting reference |

Socioboard is dormant; Fediverse-only schedulers have no traction.

**Queue-slot rules (TryPost):** a queued post keeps its slot while the slot exists, and nothing repacks the queue; "next" takes the first free slot; posts waiting for approval also hold slots; after a time-zone change a post keeps the same local clock time when it can; changes lock the channel's queue.

**What this changes in the plan:**
- No platform except Bluesky offers an idempotency key. Reconciliation by listing recent posts works on Facebook, Instagram (container status), TikTok (`publish_id`), Zalo (the article token); it does not work for member-only LinkedIn apps. Retry safety therefore has to be declared per provider and per step.
- Several platforms fetch media from a public URL. A laptop deployment cannot serve one, so self-host media posts use the platforms' upload endpoints where they exist, and the media library needs signed, time-limited public URLs when storage is public.
- Token lifetimes range from "no timer" (Facebook Page) to 24 h with rotating refresh tokens (TikTok, Zalo). A rotated refresh token must be stored in the same transaction that records the refresh, or the connection is lost.
- Zalo OA is supported by none of the projects above: a differentiator for Vietnam.
